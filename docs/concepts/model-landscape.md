本页记录当前模型注册表、尚未覆盖的诊断问题，以及新增模型需要满足的条件。模型选择和配置示例见 [model-selection.md](model-selection.md)。统一比较协议见 `strategy-pipeline/docs/concepts/benchmark-protocol.md`。

模型家族和扩展条件由 `alpha-research` 维护。`strategy-pipeline` 负责配置、命令和实验编排。

## 当前模型注册表

当前默认研究主线是 A 股，`strategy-pipeline/configs/presets/a_share.yml` 使用 `xgb_regressor`。注册表共包含五类入口。

| 模型类型 | 当前角色 | 主要用途 |
| --- | --- | --- |
| `xgb_regressor` | 默认非线性训练模型 | 预测连续收益，捕捉非线性关系和特征交互 |
| `xgb_ranker` | 排序训练模型 | 按 `trade_date` 分组学习同日横截面排序 |
| `ridge` | 线性基础校验 | 判断特征与标签是否存在稳定的线性关系 |
| `elasticnet` | 稀疏线性对照 | 检查收缩和特征稀疏化是否带来增量 |
| `fixed_score_artifact` | 固定分数产物适配器 | 读取外部冻结分数，支持确定性回放和跨系统交接 |

前四类会训练模型。`fixed_score_artifact` 只回放已有分数，不参与训练模型的优劣比较。

## 当前诊断空白

### 非线性基础校验

现有模型可以比较线性关系、XGBoost 回归和排序目标，但缺少不使用 boosting 的树模型对照。随机森林适合回答非线性关系本身是否有增量。随机森林尚未进入模型注册表，也没有配置和行为契约。

建议使用以下诊断顺序：

1. 无特征市场基准，确认策略是否只获得市场收益。
2. `ridge`，检查线性信号。
3. 随机森林候选，隔离树模型的非线性增量。
4. `xgb_regressor`，检查 boosting 带来的增量。
5. `xgb_ranker`，检查排序目标带来的增量。

`elasticnet` 可作为线性稀疏化专项对照。它和 `ridge` 回答的问题接近，无需在每次实验中同时运行。

### 生存目标

Triple Barrier 标签已经由 `alpha_research.event_labeling` 提供，可以记录屏障类型和事件时间。当前注册表没有生存模型，训练、切分和评价流程也没有接入生存目标。

接入生存模型前，应先验证事件表的覆盖率、删失分布和时间稳定性，再定义可复现的训练与评价契约。

## 什么时候扩展模型集合

| 候选方向 | 能补充的证据 | 扩展条件 |
| --- | --- | --- |
| 随机森林 | 区分树模型非线性与 boosting 增量 | 完成注册、参数契约、行为测试和统一基准比较 |
| LightGBM 或 CatBoost | 检查结果是否依赖 XGBoost 实现 | 现有协议稳定，新增依赖和维护成本可控 |
| 分位数回归或 NGBoost | 提供收益分布和尾部风险证据 | 明确评价指标，并证明分布信息会改变组合决策 |
| 生存模型 | 预测屏障事件及发生时间 | Triple Barrier 事件表稳定，生存训练与评价契约完整 |
| 模型融合 | 合并具有独立信息的稳定信号 | 各基础模型已有独立样本外证据，融合规则提前冻结 |
| 聚类、降维或深度表征 | 辅助状态识别和特征压缩 | 简单模型无法回答研究问题，新增表示有可检验增量 |

分类模型只适用于正式定义的分类标签和决策门槛。连续收益标签仍优先使用回归或排序模型。

## 新增模型的最低要求

新增模型前需要满足以下条件：

1. 说明它补充的独立诊断问题。
2. 在模型注册表中定义规范名称、别名、默认参数、拟合方法和重要度来源。
3. 补齐参数校验、行为测试和退化输出检查。
4. 使用同一数据、标签、时间切分、成本和组合构造与现有模型比较。
5. 记录训练耗时、依赖体积和维护成本。
6. 在前推验证或冻结样本外区间证明稳定增量，再考虑进入常用预设。

当前优先级是补齐可解释的诊断层，并持续收紧标签、时间切分和样本外证据。模型数量本身不作为研究进展指标。
